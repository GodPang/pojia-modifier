# v1.04.3-beta

测试版。界面这一版改了交互形态：**点了按钮不再把人拽到日志页**，每个软件的现状
直接标在列表自己那一行上；设置里多一个「启动时自检」，默认关。

## 现象

以前点「先检测一下」，页面跳到「运行记录」，二十行文本里去找哪个装了、哪个改过。
想知道「WorkBuddy 现在是什么状态」，得在一屏终端输出里认字。点「一键破甲」也一样，
跑完停在那页日志上，回主界面才发现结论条在另一页。

日志本身没问题，问题是它被当成了结果。真正想知道的信息只有一句：**每个软件现在到底
什么样**。

## 改动

### 一、动作不换页

所有功能按钮跑完都留在原页。输出照旧写进「运行记录」，但焦点不动；结果用一句话
结论条呈现（成没成、用时、去哪儿看细节），侧边栏点过去才看日志。

跑动期间软件列表压暗且不可勾选。中途改选择不会影响已经发出的那一轮，压暗是为了
不让这个误会发生。

### 二、现状标在每一行

四档，颜色分别是绿 / 琥珀 / 灰 / 淡灰：

| 档 | 标签 | 什么时候 |
|---|---|---|
| `full` | 已破甲 | 护照里记的文件逐个戳记相符 |
| `partial` | 部分破甲 | 只活下来一部分 |
| `clean` | 未破甲 | 没有记录，或记录里的文件全被换回出厂版 |
| `none` | 未安装 | 定位不到安装 / 配置目录 |

护照记的版本旧时追加「·旧版」，提示重跑一次会更新。

判据是护照 `file_stamps` 里那份「字节数:sha256 前 16 位」**逐文件**比对。绕开了两种
会骗人的信号：

- **markers**：客户端升级把文件换回出厂版之后，目录和标志物都还在。
- **主文件里那串哈希**：整树重新解包时，有些文件连标记都被换掉了，但另一些还在，
  只看主文件就会在「已破甲」和「未安装」之间反复跳。

只有逐文件比对能看见「一半被换回去」这个中间态 —— 而它恰恰是最常见的现场：客户端
一升级，注入过的文件被覆盖一部分，用户完全不知道。

本机实测就是这状态：WorkBuddy 23/36、DSH 5/6、国际版 19/21，三行都是「部分破甲」；
另有 10 个「已破甲·旧版」，7 个未安装。

### 三、`--status-json`

末行输出 `#status <JSON 数组>`，每项
`{key, name, state, label, detail, root, src, hit, total, stale}`。人看的文案随便改，
这一行的字段名和形状不动 —— 界面只认它。

### 四、启动自检（默认关）

设置页新开关，存在 `state/_settings.json` 的 `auto_scan`；命令行
`--settings scan=on|off` 读写同一份。打开后进界面就自动扫一遍，直接看到每行状态。

默认关的理由是实测数字：定位二十个目标串行 40 秒 —— 七个「未安装」的每个都要把
兜底链走到底。打开界面就白等四十秒，没人受得了。

## 顺带：扫描提速 40s → 4s

界面上要显示状态，就得先把这一步做到能用。

**并发。** 定位是 IO 等待，二十个目标扔进八个线程。进程表与命令行表的缓存各加一把锁，
过期时不会二十个线程同时重建 —— 那比串行还慢。

**Everything 熔断。** `es.exe` 装着、Everything 主程序没起时，每次查询死等 IPC 到超时。
一个目标要试三个文件名，二十个目标累计半分钟以上。改成超时一次就在本次进程内记下
`slow_until`，后面的目标直接跳过这条路。SDK 那一路（`Everything_QueryW`）是 ctypes
调用、外面打不断，扔进守护线程 join，超时就丢下并同样熔断。

**.lnk 解析结果按路径缓存。** 二十个目标都要问同一批快捷方式，不缓存就是二十倍的
文件读加结构解析。

实测：串行 40s → 并发 8 线程首次 4.2s、同进程内第二次 0.5s。
